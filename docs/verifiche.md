# vNext: esito dei cancelli preliminari

Rilevazione e aggiornamento: 21 ottobre 2026. Ambito confermato: **prima versione per uso personale**. La distribuzione a terzi richiede una nuova valutazione delle condizioni d'uso. Questo documento registra evidenza e limiti; gli script live restano fuori dalla CI.

## Fase 0a — condizioni d'uso

**Esito per la prima versione personale: consentito con limiti, come interpretazione operativa delle fonti pubbliche.** L'integrazione può essere prototipata usando le CLI installate e il login ufficiale già effettuato dall'utente. La prima versione usa un solo account attivo per provider, senza copiare credenziali, senza selettore di profili multipli e senza cambio automatico di account. Non presenta i limiti dell'abbonamento o le stime in USD come una promessa di fatturazione. Il metodo di autenticazione e la possibile fatturazione restano `sconosciuto` finché non sono verificati per la sessione concreta.

La [guida Anthropic ai piani](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan), aggiornata il 7 ottobre 2026, dice che Agent SDK, `claude -p` e app terze possono ancora usare i limiti dell'abbonamento. La [panoramica dell'Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) dice però che, senza approvazione preventiva, sviluppatori terzi non possono offrire login claude.ai o i relativi limiti nei propri prodotti. Le fonti non chiariscono il caso della distribuzione di questa estensione. Perciò **la distribuzione con login/limiti Claude è fuori dall'esito 0a attuale** e richiede chiarimento scritto da Anthropic o una diversa integrazione e fatturazione dichiarata. L'estensione non offrirà un proprio login Claude.

Per Codex, la [documentazione dell'autenticazione CLI](https://learn.chatgpt.com/docs/auth) descrive il login ChatGPT ufficiale e la memorizzazione delle credenziali in `CODEX_HOME` o nel portachiavi. La [guida Sign in with ChatGPT](https://developers.openai.com/siwc/quickstart) distingue l'uso dei piani in app open source dai partner commerciali selezionati; la [guida app-server per tale flusso](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server) prevede OAuth dell'app e gestione dei token. Sono modelli diversi dall'uso personale della CLI già autenticata. Il percorso di distribuzione va scelto e verificato separatamente; non si userà il file di token della CLI come scorciatoia per il login dell'estensione.

Prima di una distribuzione a terzi: fissare modello di distribuzione e autenticazione, ottenere il chiarimento Anthropic per Claude se si vogliono offrire login/limiti claude.ai, verificare l'idoneità del percorso OpenAI scelto, e registrare il relativo esito 0a. Il solo esito personale non vale come approvazione per il prodotto distribuito.

**Decisione per la base personale: costruire la parte mancante nell'estensione esistente**, mantenendo `Balanced` e i suoi adapter. Configurare Cline separatamente non renderebbe i suoi thread parte del workflow Countersign; estenderlo tramite SDK richiederebbe assumere il suo modello di autenticazione e di stato. Un fork aggiungerebbe un costo di manutenzione sproporzionato. Non si importano dipendenze né componenti dei quattro candidati, quindi non si attribuisce loro codice nel prodotto. La revisione dei nuovi componenti dell'estensione resta necessaria prima di attivarli.

Prima della vNext, la base MVP non aveva dipendenze runtime dichiarate. `npm audit --omit=dev --json` aveva restituito zero vulnerabilità note il 21 ottobre 2026. Una ricerca nella base non aveva trovato client HTTP o telemetria diretti; i file scritti erano il record di gate Claude sotto `~/.countersign`, un file schema Codex in una directory temporanea e i file di prova temporanei, rimossi alla fine. Le CLI gestiscono autonomamente autenticazione e stato. L'Agent SDK è stato poi aggiunto come dipendenza runtime della chat ed è stato ricontrollato con `npm audit --omit=dev`.

L'Agent SDK installato nello spike occupava circa **338 MB** con dipendenze, di cui circa **278 MB** per il binario Linux x64 incluso. La dipendenza runtime è stata poi aggiunta all'estensione; il VSIX esclude il binario opzionale e usa la CLI locale verificata. Il VSIX prodotto misura circa **11,55 MB** compressi; l'SDK e le sue dipendenze runtime contano circa 8.000 file interni, limite di packaging da ottimizzare prima di una distribuzione ampia. L'SDK documenta `pathToClaudeCodeExecutable` per scegliere il binario esterno.

`node spikes/claude-sdk/check-local-compat.mjs` ha completato senza prompt né inferenza l'handshake tra SDK 0.3.306 e CLI locale 2.1.109. I successivi spike live hanno verificato anche streaming, ripresa, isolamento e callback di permesso su tale coppia. **Scelta per il VSIX Linux personale:** dipendenza Agent SDK con binario opzionale escluso dal pacchetto, eseguibile Claude installato e verificato per versione esatta. L'estensione non sostituirà né aggiornerà la CLI dell'utente. Se la versione cambia, il gate va ripetuto. Questa scelta va rivalutata per altre piattaforme e per la distribuzione a terzi.

L'installazione `--omit=optional` dello spike occupa circa **61 MB**, e `startup()` ha completato l'handshake con la CLI locale senza il binario incluso e senza prompt. Il progetto dichiara l'SDK come dipendenza runtime. Il VSIX è stato installato in un profilo VS Code isolato; `chat-mock` ha aperto la sidebar, completato una risposta e creato un secondo thread dall'estensione impacchettata. L'SDK estratto dal VSIX ha restituito il catalogo Claude con la CLI locale senza inferenza. `npm audit --omit=dev` ha riportato zero vulnerabilità note alla verifica locale.

### Scelta della superficie

Il prototipo VS Code ha registrato entrambe le API. La [Chat Participant API](https://code.visualstudio.com/api/extension-guides/ai/chat) offre stream e riferimenti, ma il selettore modello del composer appartiene alla Language Model API di VS Code e non può rappresentare da solo le coppie provider/modello/effort restituite dalle CLI, né aggiungere i controlli di modalità e permessi richiesti. La [WebviewView](https://code.visualstudio.com/api/extension-guides/webview) può presentare questi controlli nella sidebar con CSP, risorse locali e messaggi tipizzati. **Superficie scelta: WebviewView**, con store e logica nell'extension host. Il prototipo non viene registrato nell'estensione pubblicata.

### Implementazione verificata e limiti rimasti

1. `verifyClaudeChatGate()` del prodotto ha ripetuto due turni temporanei con controllo positivo del hook, ripresa e soppressione delle impostazioni di progetto, poi ha salvato un record con SDK **0.3.306** e CLI **2.1.109 (Claude Code)**. Il prodotto confronta entrambe le versioni prima di ogni turno. Il gate MVP rimane separato.
2. `smoke-chat-adapters.mjs --live` ha completato un turno streaming e sessione con ciascun adapter di prodotto. `smoke-chat-write.mjs --live` ha provato scrittura Claude autorizzata, diff e ripresa. La prima prova ha rivelato che il callback positivo della coppia SDK/CLI richiede `updatedInput` benché il tipo lo dichiari facoltativo; l'adapter è stato corretto e la prova successiva è passata.
3. Claude emette eventi `rate_limit_info` con stati `allowed`, `allowed_warning` e `rejected`; un evento `allowed` non significa quota esaurita. La chat mostra lo stato quando arriva. Codex non ha una quota affidabile esposta in questa integrazione. `model/list` resta un catalogo, non garanzia di accesso. L'effort Claude effettivo può non essere riportato; la UI distingue richiesto da effettivo.
4. La sidebar e lo store sono ora nel prodotto con thread, ricerca, modalità chat personalizzate, provider reali e percorso `Balanced`. Il lock condiviso fra questi percorsi segnala nella UI un repository occupato, ma coordina solo lo stesso extension host. Compilazione, lint, 60 test e il caso `chat-mock` sul VSIX passano. Il caso integrato chiude e riapre la sidebar conservando i due thread; il test host usa storage in memoria, quindi non prova un riavvio completo della normale finestra VS Code. Restano non verificati l'interazione completa dei permessi dalla UI nel VSIX, il supporto macOS/Windows, gli allegati binari e le fasi condizionate `Strict` e cambio automatico di account.

Le prove che inviano prompt reali, modificano repository temporanei o usano quota sono script manuali `--live`; in questa sessione l'utente le ha autorizzate e ha chiesto di procedere senza ulteriori richieste ripetitive. La CI resta solo mock.
