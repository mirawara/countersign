# Verification results

Measured and updated on 21 October 2026. Scope: **a personal build for the author's own use**. Distributing the extension to other people needs a separate review of the providers' terms, which is kept in [third-party-accounts.md](third-party-accounts.md). This page records evidence and limits; the live scripts stay out of CI.

## Terms of use

**Outcome for a personal build: permitted with limits, as an operational reading of the public sources.** The integration can be built on the installed CLIs and the official login the user already performed. It uses one active account per provider, copies no credentials, offers no profile switcher and performs no automatic account switching. It does not present subscription limits or US dollar estimates as a billing promise. The authentication method and the possible billing stay `unknown` until verified for the concrete session.

[Anthropic's plan guidance](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan), updated on 7 October 2026, states that the Agent SDK, `claude -p` and third-party applications can still use subscription limits. The [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview) states that, without prior approval, third-party developers may not offer claude.ai login or its usage limits in their own products. The sources do not settle the case of distributing this extension, so **distribution with a Claude login or Claude usage limits is outside this outcome** and needs a written clarification from Anthropic or a different integration with declared billing. The extension will not offer a Claude login of its own.

For Codex, the [CLI authentication documentation](https://learn.chatgpt.com/docs/auth) describes the official ChatGPT login with credentials stored in `CODEX_HOME` or the system keyring. The [Sign in with ChatGPT guide](https://developers.openai.com/siwc/quickstart) distinguishes plan use in open-source applications from selected commercial partners, and the [app-server guide for that flow](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server) expects the application's own OAuth and token handling. Those are different models from personal use of an already authenticated CLI. A distribution path must be chosen and verified separately, and the CLI's token file will not be used as a shortcut for an in-product login.

Before distributing to other people: fix the distribution and authentication model, obtain Anthropic's clarification if claude.ai login or limits are to be offered, verify eligibility for the chosen OpenAI path, and record that outcome. The personal outcome is not an approval for a distributed product.

**Decision: build the missing part inside the existing extension**, keeping `Balanced` and its adapters. Configuring Cline separately would not make its threads part of the Countersign workflow; extending it through its SDK would mean adopting its authentication and state model; forking it would add disproportionate maintenance cost. No dependency or component of the four candidates is imported, so none of their code is attributed in the product. Reviewing the extension's own new components stays necessary before enabling them.

Before this work, the MVP base declared no runtime dependencies, and `npm audit --omit=dev --json` reported no known vulnerabilities on 21 October 2026. A search of the base found no direct HTTP client or telemetry; the files written were the Claude gate record under `~/.countersign`, a Codex schema file in a temporary directory, and temporary test files removed at the end. The CLIs manage authentication and state themselves. The Agent SDK was then added as a runtime dependency of the chat and re-checked with `npm audit --omit=dev`.

The Agent SDK installed in the spike occupied roughly **338 MB** with dependencies, about **278 MB** of which is the bundled Linux x64 binary. The runtime dependency was then added to the extension, the package excludes the optional binary, and it uses the verified local CLI. The resulting package is about **11.7 MB** compressed, and the SDK with its runtime dependencies accounts for roughly 8,000 internal files — a packaging limit to address before any wide distribution. The SDK documents `pathToClaudeCodeExecutable` for choosing the external binary.

`node spikes/claude-sdk/check-local-compat.mjs` completed the handshake between SDK 0.3.306 and the local CLI 2.1.109 with no prompt and no inference. Later live probes verified streaming, resumption, isolation and permission callbacks on that pair. **Choice for the personal Linux package:** the Agent SDK as a dependency with its optional binary excluded, and the installed Claude executable verified at an exact version. The extension will never replace or upgrade the user's CLI. If the version changes, the gate must be repeated. This choice has to be revisited for other platforms and for distribution.

An `--omit=optional` install of the spike occupies about **61 MB**, and `startup()` completed the handshake with the local CLI without the bundled binary and without a prompt. The package was installed into an isolated VS Code profile, where `chat-mock` opened the sidebar, completed a reply and created a second thread from the packaged extension. The SDK extracted from the package returned the Claude catalogue using the local CLI without inference. `npm audit --omit=dev` reported no known vulnerabilities at local verification.

### Choosing the chat surface

The VS Code prototype registered both APIs. The [Chat Participant API](https://code.visualstudio.com/api/extension-guides/ai/chat) offers streaming and references, but the composer's model picker belongs to VS Code's Language Model API: on its own it cannot represent the provider/model/effort combinations the CLIs return, nor add the required mode and permission controls. A [WebviewView](https://code.visualstudio.com/api/extension-guides/webview) can present those controls in the sidebar with a strict CSP, local resources and typed messages. **Chosen surface: WebviewView**, with the store and the logic in the extension host. The prototype is not registered in the published extension.

### What is implemented, and what is still open

1. The product's `verifyClaudeChatGate()` repeated two temporary turns with a positive hook check, resumption and suppression of project settings, then stored a record for SDK **0.3.306** and CLI **2.1.109**. The product compares both versions before every turn. The MVP gate stays separate.
2. `smoke-chat-adapters.mjs --live` completed a streaming turn and a session with each product adapter. `smoke-chat-write.mjs --live` exercised an authorized Claude write, the diff and resumption. The first attempt revealed that the positive callback for this SDK/CLI pair requires `updatedInput` even though the type declares it optional; the adapter was corrected and the next run passed.
3. Claude emits `rate_limit_info` events with the states `allowed`, `allowed_warning` and `rejected`; an `allowed` event does not mean quota is exhausted. The chat shows the state when it arrives. Codex exposes no reliable quota in this integration. `model/list` remains a catalogue, not a guarantee of access. The effective Claude effort may not be reported, so the UI distinguishes requested from effective.
4. The sidebar and store are in the product, with threads, search, custom chat modes, real providers and the `Balanced` path. The lock shared between those paths reports a busy workspace in the UI but coordinates a single extension host only. On 22 October 2026, `npm test` passed **86 tests across 17 files**, including test typechecking; `npm run compile` and `npm run lint` passed. The current VSIX passed all five selected packaged mock cases (`chat-mock`, `mock-clean`, `mock-finding`, `mock-dismiss`, `mock-validation-failed`) against a temporary fixture. The separate `cancel-during-check` case was not run because no canonical fixture is checked into this repository; it remains unverified. Local Codex app-server `thread/start` accepted a non-Git folder without an inference request. Still unverified: a complete live Claude plus Codex run in dirty Git and non-Git folders, `cancel-during-check`, the complete new permission interaction from the packaged UI, macOS and Windows support, binary attachments, and the conditional `Strict` and account-switching phases.

Probes that send real prompts, modify temporary repositories or consume quota are manual `--live` scripts, run with explicit authorization. CI stays mock-only.
